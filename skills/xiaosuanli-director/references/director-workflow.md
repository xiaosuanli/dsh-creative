# 公共导演能力与制作指引

## 导演台能做什么

- **工程与章节**：创建、列出并打开工程和章节，一个聊天固定一个章节。
- **小说、文章转视频**：解析正文，整理人物、场景与分镜；按用户要求浓缩剧情，再制作成片。
- **一键复刻视频**：读取已上传视频，解析原有剧情和镜头，按用户要求调整画风、人物或语言，接续素材、视频制作与导出。只要求解析时停在解析成果，不自动生成。
- **剧情与分镜编辑**：新增或修改幕、镜头、对白、制作描述、时长和生成设置，绑定人物与场景素材。
- **图片与视频**：创建人物/场景/物品素材图，生成单镜或整章视频，选择已有结果，恢复失败部分并导出成片。
- **账号与额度**：查看已授权的账号、会员、积分与可用权益。

这些是产品能力；实际操作以当前渠道已提供的工具、权限与回执为准，不能把未接入的能力说成已完成。复刻视频或较长小说时读取[导入与复刻使用说明](import-and-remake.md)。

## 单章输入限制

**每章文本最多 20,000 字；单章导入复刻的源视频最长 3 分钟（180 秒），当前视频入口接受 15～180 秒。** 提交前核对完整输入，不把字数当 token 数。超过范围时提示分章或选择视频片段，由用户明确范围；不偷偷截断，也不把超长材料切成多次请求塞进同一章。用户已要求浓缩时，可完整理解后按目标时长改编，并说明使用的是改编稿。

3 分钟是导入源视频的上限，不是所有视频都必须生成 3 分钟。短文改编时长按用户要求规划；忠实复刻默认保持所选源片段的时长和关键情节。

## 对外沟通与隐私

只向用户说明功能、操作选择、成果与可行动的错误。不要透露内部模型编排、服务拓扑、数据库、部署/运维流程、内部地址、账号配置或日志；不要读取或展示访问令牌、PKCE verifier 及他人工程数据。用户内容只用于当前授权任务，不写进公共 skill、样例或安装包。工具返回的技术回执用于恢复执行，用户通常只需看到作品进度和编辑链接。

## 创建工程、章节与图形化编辑

用户要求新建时使用 `create_project(title, requestId)`；返回的工程已含空白第一章，先呈现让用户选择，不重复创建。已有工程需要新章时，先读 `chapters` 的版本和章节所属剧本，再用 `create_chapter(projectId, scriptId, title, requestId, expectedVersion)` 创建空白章。创建不等于解析或生成；取得成功回执后才 `open_chapter`。已绑定章节的聊天要创建其它工程/章，应提示新建聊天，不能原地换章。未开放创建工具或权限不足时说明缺项，给网页入口，不能假报创建成功。

创建、打开或修改完成后，提供工具返回的 `editorUrl`，提示：“可以打开导演台网页，用图形界面继续调整剧情、分镜、素材和生成设置。”通过系统默认浏览器打开用户要求查看的链接。只使用当前环境的站点：测试包打开测试网站，正式包打开正式网站。网页支持工程链接 `/apps/automated-director?project=<工程ID>`；章节在页面内选择，不编造章节深链或内部控制台地址。用户在网页修改后先刷新工程版本，再继续编辑，保留其图形化修改。

## 原文、改编稿与时长

完整阅读用户提供的原文，理解人物动机、关系变化、主要因果、信息揭示顺序、转折、高潮和结尾；保留悬念成立所需的未知信息直到既定揭示时刻，再确定观众在目标时长内能够理解与感受到的故事。用户要求浓缩时，先自主写出可拍摄的完整改编稿：保留主因果和重要关系，合并重复解释、支线和同义对白，把适合视觉表达的信息落实到行动与画面。新增拍摄设定服务原故事和用户要求，不能把猜测当作原文事实。

改编稿明确场景、人物、可见行动、对白/声音、节奏和结尾，分配时间给事件、动作完成、对白与必要留白。先核对自然表演是否放得进目标时长；压缩叙事内容，不靠全员抢话、持续旁白或简单加速播放装下原文。时长由本次用户请求决定，不固定全片秒数、镜头数或统一分段长度。

原文留在会话来源中；改编稿标明是面向目标时长的新制作版本。有压缩/改编指令时，将**完整改编稿**交给解析 API；未要求改编时交付完整选定正文。不能静默截断原文，也不能仅传一句摘要却宣称完成全部剧情设计。

## 复用导演台解析分镜

整篇文本默认通过已有 `text_import` 创建分镜、资源卡和基础连线；逐节点创建只用于明确的局部增补，不替代解析主流程。

1. 读取 `project_get` 的 `document.currentScriptId/currentChapterId`、对应章节及 `project.currentVersion`。未解析空章可提交；已解析章节先复用结果，不覆盖用户现有工作。
2. `text_import` 使用当前工程、目标 `chapterId`、标题、完整制作稿、用户确定的 `targetDurationSeconds/resolution`，以及稳定 `requestId/expectedVersion`。它自动准备空章，无需先手动创建幕和镜头。权限需 `director:run` 与 `project:write`；缺项说明具体授权问题。
3. 保存原 `kind=import/taskId`，通过 `import_get` 查询。解析成功后 `project_get(scope=full)` 读回目标章节、幕、视频节点、资源与连接。
4. 核对实际节点累计时长、叙事顺序、对白可演性、关系和结尾是否符合已确定的成片意图。`targetDurationSeconds` 是规划目标，不是实际命中证明。仅修正偏离的节点、时长、制作描述或资源连接，保留正确结果。新写操作使用最新版本。

当前对话只处理已打开的一章；多章节源文先确认本章范围，其它章节分别开新对话。当前没有任意节点删除/重排或已解析章节覆盖工具，缺少能力时保留结果并指出具体缺口，不暗中复制工程绕过。

## 素材与人物一致性

读取 `image_models` 的当前可用模型、价格和 `toolParameters`。模型目录的宽能力不等于当前生图入口都支持；不编造模型、参考图或分辨率参数。

围绕要制作的视频节点确定必要人物、场景和关键物品。先复用本工程已有且适用的参考图与在途任务；仅为缺失的必要资源生图。资源卡描述稳定外观，分镜描述当时的行动、表情、位置和声音。主角跨镜头使用同一资源身份和绑定参考，不每镜新建人物。

`resource_update` 的 description 保存设定，imagePrompt 保存实际生图提示词。人物/物品未自定义 imagePrompt 时优先使用产品默认设定图版式；自定义时人物为白底横向头像与正侧背无头身体设定，物品为白底独立完整物品。视觉风格贯穿卡片、镜头和生成参数。

通过 `image_generate` 提交必要图片，记录每个任务；完整成片流程需要等待图片成功并已绑定。`image_status` 返回成功但绑定冲突时，用最新版本和 `image_bind` 复用原图。用 `resource_bind` 补缺少的同章节资源连接；已有图片但未连接不能称为视频已经采用。

## 视频制作与结果选择

`videoNodes[].description` 是下一次视频生成的有效剧情输入，幕摘要和来源正文不会自动改写各镜头。必要的描述修正写入 `node_update(kind=video)`，明确当前片段的场景、参考人物、起始状态、运镜、连续动作、表情及完整对白/声音；时间从该片段 0 秒起算，并与节点时长一致。保留整片因果和前后状态。

解析后的资源卡是占位，视频入口不会代你生成参考图。先确认已连接必需素材均有实际图片且已绑定，再读回最新版本、节点时长、参考绑定与顺序。准备计划时保存输入快照，后续补绑不自动改变原计划；恢复时核对原任务实际采用的版本和素材。单镜用 `video_generate`，明确章节/幕范围可用 `generation_start`；显式使用用户要求的 resolution/aspectRatio。补齐缺失或更新新剧情时采用 `incremental:true`，保留未变化的成功片段。需要整幕重新导演时才用 `director_start`，它可能已提交素材和视频，不重复提交相同范围。

`task_get` 查询原视频任务。生成成功后核对 `selectedResultId`；尚未选用时，从 `generation.attempts[].videoResultId` 获取与 nodeId 对应的真实成功结果，用 `result_select` 选择。绑定冲突通过选择原结果恢复，不重做收费生成。

## 异步继续与成片终点

| 类型 | 查询工具 |
| --- | --- |
| import | import_get |
| image | image_status |
| video | task_get |
| director | director_get |
| export | export_get |

以工具实际进度区分“等待、生成中、成功、失败”；已创建任务不代表已经生成，向用户使用清楚的业务描述。

用户只要求提交图片/视频时，全部受理即可报告已入队。**用户要求完整成片时，入队、图片成功或视频片段完成都不是终点**：继续处理依赖、选择结果，并用 `export_start(scope=chapter)` 导出正确上下文，`export_get` 确认成片成功。

等待调用可交给宿主支持的长等待/任务恢复能力；模型不要连续空转查询相同状态。记录原任务和当前阶段，恢复时查原任务并从其结果继续。需要结束本轮等待时明确“制作仍在进行”，不能标记整体完成或让用户逐步催促才能继续。

每次新写使用最新 `expectedVersion` 和稳定 `requestId`。响应丢失时查询原 taskId；没有 taskId 时保留原 requestId、参数和 expectedVersion 重放。版本冲突先读当前状态，新修改才换键。失败只恢复失败部分；重复同一不可恢复错误、权限或余额不足时停止盲目重试，报告真实阻点。

交付前核对导出范围覆盖所有需要的当前视频、剧情时长、画幅、分辨率和声音要求。只有实际媒体证据才能称成片时长已命中；节点时长之和仅是计划时长。返回工具提供的成片地址与工程信息；没有观看实际画面时不宣称画面质量已验收。`account` 的通用积分与视频积分分别解释，缺失值不当作零。
